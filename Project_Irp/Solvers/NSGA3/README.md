# NSGA3 — NSGA-III solver for the many-objective IRP

Reference implementation of NSGA-III (via [pymoo](https://pymoo.org)) applied to
the Inventory Routing Problem (IRP) with 4 objectives. Used both as the
production solver and as the baseline QI-NSGA-III (`QINSGA3/`) is compared
against.

## Modules

| File | Role |
|---|---|
| `problem.py` | `IRPProblem` — pymoo `ElementwiseProblem` definition: decision-variable bounds (`xl`/`xu`), objective/constraint count, and the `_evaluate` call that decodes + scores one chromosome. Shared with `QINSGA3/` (imported directly, not duplicated). |
| `decoder.py` | `decode_chromosome` (flat array → quantities + priorities dicts) and `build_routes` (greedy nearest-neighbour heuristic turning quantities into feasible vehicle routes, enforcing depot-stock and time-window constraints). |
| `evaluator.py` | The 4 objective functions computed from a decoded route: `compute_f1` (logistics cost), `compute_f2` (CO₂ emissions), `compute_f3` (travel time), `compute_f4`/`compute_f4_detail` (working capital / BFR). |
| `metrics.py` | Pareto-front quality indicators — Hypervolume (HV), Generational Distance (GD), Inverted GD (IGD), Spacing — computed via pymoo, optionally against a shared ideal/nadir for cross-run/cross-algorithm comparability. |
| `main.py` | CLI + API entry point: `run_nsga3()` runs N independent seeded replications and caches the Pareto chromosomes; `run_nsga3_report()` also writes the HTML dashboard; `render_from_instance()` re-scores a cached run against a (possibly edited) instance file without re-optimising. |
| `report_builder.py` | Shared report-building helpers (`_evaluate_pareto`, `_build_report_data`) — also imported by `QINSGA3/main.py` so both solvers produce an identical report schema. |
| `report.py` | Self-contained HTML report template + `write_report`/`generate_and_open`/`render_html`. |
| `nsga3_chromosomes.json` | Cached Pareto-front chromosomes from the last run(s) (gitignored, regenerated by `main.py`; consumed by `sensitivity/compare_qinsga3_vs_nsga3.py` as the NSGA-III reference). |
| `nsga3_report.html` | Generated HTML dashboard (gitignored, regenerated by `main.py`). |

## Algorithm

Standard NSGA-III (Deb & Jain, 2014), used unmodified from pymoo:

1. **Sample** an initial population of `pop_size` chromosomes uniformly across `[xl, xu]` (`FloatRandomSampling`).
2. **Evaluate** f1–f4 and all constraints for every chromosome (`IRPProblem._evaluate`, via `decoder.py` + `evaluator.py`).
3. **Survive**: merge parent + offspring populations, non-dominated sort, associate each solution to the nearest reference direction (Das-Dennis simplex-lattice points), and keep the best `pop_size` via niching — the elitist replacement step that defines NSGA-III.
4. **Vary**: SBX crossover + polynomial mutation (PM) produce the next generation's offspring.
5. Repeat for `n_gen` generations; the final population's non-dominated front is the returned Pareto set.

## Parameters and their references

| Parameter | Value | Rationale / reference |
|---|---|---|
| `pop_size` | 200 | Fixed search budget, matched to `QINSGA3` for a fair comparison. |
| `n_gen` | 300 | Same reasoning — equal generation budget across both solvers. |
| SBX `prob` | 0.9 | Standard crossover probability, Deb (2001) *Multi-Objective Optimization Using Evolutionary Algorithms*. |
| SBX `eta` | 20 | Distribution index — higher = offspring closer to parents (more exploitative); the value used in Deb & Jain (2014)'s own NSGA-III experiments. |
| PM `eta` | 20 | Same rationale, polynomial mutation (Deb & Agrawal, 1995). |
| PM `prob` | `1 / D` (D = number of decision variables) | Deb & Jain (2014)'s recommended per-gene mutation rate. |
| `N_PARTITIONS` (Das-Dennis) | 8 → 165 reference directions for 4 objectives | Das & Dennis (1998) systematic simplex-lattice design, as prescribed by Deb & Jain (2014) for generating NSGA-III's reference points. |

## Objectives (`evaluator.py`)

- **f1 — Logistics cost**: transport + depot holding + time-window penalty costs.
- **f2 — CO₂ emissions**: linearised CMEM model (Bektas & Laporte, 2011).
- **f3 — Travel time**: total arc travel time across all trucks/periods.
- **f4 — Working capital (BFR)**: stock value + accounts receivable − accounts payable, using DIO/DSO/DPO day-count conventions.
