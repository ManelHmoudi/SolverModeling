# NSGA3 — NSGA-III solver for the many-objective IRP

Reference implementation of NSGA-III (via [pymoo](https://pymoo.org)), applied
to the Inventory Routing Problem (IRP) with 4 objectives. Serves both as a
production solver and as the baseline `Solvers/QINSGA3/` is benchmarked
against.

## Modules

| File | Role |
|---|---|
| `problem.py` | `IRPProblem` — pymoo `ElementwiseProblem` definition: decision-variable bounds (`xl`/`xu`), objective/constraint counts, and the `_evaluate` call that decodes and scores one chromosome. Shared with `Solvers/QINSGA3/` (imported directly, never duplicated). |
| `decoder.py` | `decode_chromosome` (flat array → quantities + priorities) and `build_routes` (greedy nearest-neighbour heuristic turning quantities into feasible vehicle routes, enforcing depot-stock and time-window constraints). |
| `evaluator.py` | The 4 objective functions computed from a decoded route: `compute_f1`, `compute_f2`, `compute_f3`, `compute_f4`/`compute_f4_detail`. |
| `metrics.py` | Pareto-front quality indicators — Hypervolume (HV), Generational Distance (GD), Inverted GD (IGD), Spacing — via pymoo, optionally against a shared ideal/nadir for cross-run/cross-algorithm comparability. |
| `main.py` | CLI + API entry point. `run_nsga3()` runs N independent seeded replications and caches the Pareto chromosomes; `run_nsga3_report()` also writes the HTML dashboard; `render_from_instance()` re-scores a cached run against an (edited) instance file without re-optimising. |
| `report_builder.py` | Shared report-building helpers (`_evaluate_pareto`, `_build_report_data`), also imported by `Solvers/QINSGA3/main.py` so both solvers produce an identical report schema. |
| `report.py` | Self-contained HTML report template + `write_report` / `generate_and_open` / `render_html`. |
| `nsga3_chromosomes.json` | Cached Pareto chromosomes from the last run(s) — gitignored, regenerated by `main.py`; consumed by `sensitivity/compare_qinsga3_vs_nsga3.py` as the NSGA-III reference. |
| `nsga3_report.html` | Generated HTML dashboard — gitignored, regenerated by `main.py`. |

## Algorithm

Standard NSGA-III (Deb & Jain, 2014), used unmodified from pymoo:

1. **Sample** an initial population of `pop_size` chromosomes uniformly across `[xl, xu]` (`FloatRandomSampling`).
2. **Evaluate** f1–f4 and all constraints for every chromosome (`IRPProblem._evaluate`, via `decoder.py` + `evaluator.py`).
3. **Survive** — the elitist replacement step that defines NSGA-III: merge parent and offspring populations, non-dominated sort, associate each solution to the nearest reference direction (Das-Dennis simplex-lattice points), and keep the best `pop_size` via niching.
4. **Vary** — SBX crossover + polynomial mutation (PM) produce the next generation's offspring.
5. Repeat for `n_gen` generations; the final population's non-dominated front is the returned Pareto set.

The step that makes NSGA-III "many-objective capable" (where NSGA-II's
crowding distance degrades past ~3 objectives) is step 3's reference-point
niching: instead of preferring solutions in *sparse regions of the front*
(crowding distance — a purely relative, pairwise notion that breaks down in
high dimensions because almost every solution ends up "far" from its
neighbours), NSGA-III preferds solutions that are *close to a
pre-distributed set of reference directions* covering the whole objective
simplex uniformly. This turns diversity preservation into a well-posed
assignment problem (one reference direction → its niche) regardless of how
many objectives there are.

## Pseudocode

Deb & Jain (2014), Algorithm 1 (`NSGA-III(P₀, Z, N_gen)`), exactly as pymoo
implements it — nothing in this project modifies pymoo's own `NSGA3`
survival or mating:

```
Input : reference directions Z = {z¹,…,z^H}  (Das–Dennis, N_PARTITIONS=8 → H=165)
        population size N (bumped to max(N, H) if H > N)
        generation budget N_gen

P₀ ← RandomInit(N)                       # FloatRandomSampling, uniform in [xl, xu]
Evaluate(P₀)                             # f1..f4 + constraints G, via IRPProblem._evaluate
for t = 0 … N_gen-1:
    Qₜ ← Variation(Pₜ)                   # selection + SBX(pc=0.9, η=20) + PM(pm=1/D, η=20)
    Evaluate(Qₜ)
    Rₜ ← Pₜ ∪ Qₜ                         # combined pool, size 2N
    (F₁, F₂, …) ← NonDominatedSort(Rₜ)   # constraint-domination: feasible always beats infeasible,
                                          # among infeasible the smaller total violation wins
    Sₜ ← ∅ ; i ← 1
    while |Sₜ| + |Fᵢ| ≤ N:
        Sₜ ← Sₜ ∪ Fᵢ ; i ← i+1
    if |Sₜ| = N:
        P_{t+1} ← Sₜ                     # exact fit, no niching needed this generation
    else:
        Fₗ ← Fᵢ                          # the last, partially-included front
        Normalize(Sₜ ∪ Fₗ)               # ideal point z* = componentwise min;
                                          # extreme points via ASF, nadir from their intercepts
        for x in Sₜ ∪ Fₗ:
            Associate(x, Z)              # nearest reference direction, by perpendicular distance
                                          # in normalized objective space
        ρⱼ ← niche count of Sₜ on each direction j        # solutions already selected per direction
        K ← N − |Sₜ|                                      # remaining slots to fill from Fₗ
        while K > 0:
            j* ← argmin_j ρⱼ  (ties broken randomly)      # least-crowded direction
            if ∃ member of Fₗ associated to j*:
                move its closest-to-j* member from Fₗ into Sₜ ; ρⱼ* += 1 ; K -= 1
            else:
                ρⱼ* ← ∞                                   # exclude exhausted direction, retry
        P_{t+1} ← Sₜ
return non-dominated front of P_{N_gen}
```

`Normalize` (extreme-point/intercept method, Deb & Jain 2014, §IV-A) and
`Associate`/niching together form pymoo's `ReferenceDirectionSurvival` —
the same object QI-NSGA-III reuses directly for its own environmental
selection (see `Solvers/QINSGA3/README.md`'s pseudocode) rather than
reimplementing it.

## Parameters and references

| Parameter | Value | Reference |
|---|---|---|
| `pop_size` | 200 | Fixed search budget, matched to `Solvers/QINSGA3` for a fair comparison |
| `n_gen` | 300 | Equal generation budget across both solvers |
| SBX crossover probability (`pc`) | 0.9 | Deb & Agrawal (1995) [1] |
| SBX distribution index (`eta_c`) | 20 | Deb & Agrawal (1995) [1] |
| PM distribution index (`eta_m`) | 20 | Deb & Agrawal (1995) [1] |
| PM mutation probability (`pm`) | 1/D (D = number of decision variables) | Deb & Jain (2014) [2] |
| Reference-point construction | Das-Dennis, `N_PARTITIONS = 8` → 165 directions (4 objectives) | Das & Dennis (1998) [3], as prescribed by Deb & Jain (2014) [2] |

### References

[1] Deb, K., & Agrawal, R. B. (1995). Simulated binary crossover for continuous search space. *Complex Systems*, 9(2), 115–148.
[2] Deb, K., & Jain, H. (2014). An evolutionary many-objective optimization algorithm using reference-point-based nondominated sorting approach, part I: Solving problems with box constraints. *IEEE Transactions on Evolutionary Computation*, 18(4), 577–601.
[3] Das, I., & Dennis, J. E. (1998). Normal-boundary intersection: A new method for generating the Pareto surface in nonlinear multicriteria optimization problems. *SIAM Journal on Optimization*, 8(3), 631–657.

## Objectives

Computed by `evaluator.py` from a decoded route:

| | Objective | Definition |
|---|---|---|
| **f1** | Logistics cost | Transport + depot holding + time-window penalty costs |
| **f2** | CO₂ emissions | Linearised CMEM model (Bektas & Laporte, 2011) |
| **f3** | Travel time | Total arc travel time across all trucks and periods |
| **f4** | Working capital (BFR) | Stock value + accounts receivable − accounts payable, using DIO/DSO/DPO day-count conventions |

## Usage

```bash
python -m Solvers.NSGA3.main                                       # instance_25_clients.json, 1 run
python -m Solvers.NSGA3.main --instance 100 --runs 20               # 100-client instance, 20 seeded runs
python -m Solvers.NSGA3.main --instance 25 --pop 200 --gen 200 --runs 5
```

Or via the local web UI: `python main.py` → select an instance → run NSGA-III.
